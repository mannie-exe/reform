# Native addon example

This separate NeoForge mod consumes only the staged `design.inherent:reform` Maven artifact. It does not use the library's source sets, Compat, Skyweave or the modpack. The ordinary example JAR excludes the opt-in native probe.

`NativeExample` declares a small typed preference record through public record derivation. Its physically client-only `ClientExample` uses the [client JSON factory](../../docs/development/client-json.md), explicit menu registration and the `reformprefs` native client command. The library supplies native setup, bounded workers, owned storage, shared GUI/command operations, the generated form and shutdown. The example supplies no executor, serializer or editing-session infrastructure.

`CreationExample.editor(parent, original)` separately demonstrates the public world-recipe factory for a bounded three-layer flat-world soil-depth setting. It preserves unedited dimensions through the native replacement API and registers no replacement editor for vanilla presets. The native form runner executes it in a real creation screen, without creating a playable world.

Run `./gradlew --no-daemon check build` from the repository root to compile this example and its probe against the exact candidate artifact. This compiles native APIs without launching a game. It also runs the independent headless consumer and core/tooling checks.

For a disposable client check, first build/stage the library, obtain sustained desktop focus, then run from the repository root:

```sh
python3 tools/native_form_probe.py --java-home /path/to/jdk21
```

The runner refuses an existing `examples/native/runs/client`, creates its own marked fixture and runs thirteen bounded 2 GiB Minecraft clients sequentially. The probe exercises registration refusals, actual menu entry, native fields/invalid drafts/save/reflow/close/reopen, persisted preferences in a second JVM, malformed-file retention/recovery, a pending retry started by an initialization observer and settled at native shutdown, recursive controls and their reopen, reference pickers and their reopen, numeric controls and their reopen, then local dependencies and their reopen. `--lifecycle-only` selects the shutdown control; `--recipe-only` selects native original-context recipe controls; `--structured-only` selects recursive controls/reopen; `--references-only` selects reference pickers/reopen; `--numeric-only` selects numeric controls/reopen; `--dependencies-only` selects local availability/reopen. The first client also posts the actual client command-registration event and runs native Brigadier operations on the same GUI-saved document, covering invalid input, staged edits, validation, comparison, export/copy components, actual save/publication and retained status/cancel. Its feedback sink is captured at the main menu; this does not qualify a player chat packet or physical clipboard. Reports/screenshots go to ignored `build/reports/native-form/`. Only the matching task-owned fixture and logs are removed. Personal instances, servers and worlds are not used.

`StructuredExample` is an independently registered client JSON profile for those recursive controls. The probe edits actual native inputs/buttons, follows row identity across copy/move, repairs duplicates, restores invalid inactive values and confirms obsolete widget callbacks cannot target restored branches. It preserves unchanged disk until explicit Save and checks the resulting runtime value and fresh-JVM reopen. This is an inline generated form, separate from the reference-picker suite; catalog/detail remains required.

`ReferenceExample` supplies explicit block/tag and client language-resource snapshots through the ready owner, plus a deliberately absent optional donor and an unbound source. It prepares/replaces sources explicitly; ordinary rendering and typing do not enumerate resources. The picker fixture uses native text/pointer events to search/page/inspect, reject malformed/unknown/unavailable choices, refresh a same-label source replacement, retain an over-limit authored ID with diagnostics and repair it. Choosing changes the draft; the fixture separately saves/reopens and checks auxiliary-screen teardown. This example does not replace actual world-specific registry or resource reload policy.

`NumericExample` declares duration, distance, probability, already stored percent, explicit sliders and an owner-validated min/max pair through the same client factory. Its native fixture distinguishes display-only switches from staged input, checks exact integer refusal and canonical steps, retains a conversion failure whose text otherwise parses as a stored number, and verifies save spelling/caret/selection, narrow reflow, retired callbacks and second-JVM canonical file/runtime values. It starts with a deliberately malformed owned file, repairs it through initialization retry and checks that the successor retains its authored presentation. Actual pointer drags exercise latest-value coalescing. Range repair preserves both endpoints and the owner's diagnostics without clamping the other field. Custom finite-decimal failure controls exercise explicit refusal without rounding exact text.

`DependencyExample` adds local boolean/choice/optional-input gates through the same generated form. Its fixture checks distinct known-false/unknown states, retained invalid values, complete owner validation while inactive, numeric and collection action gating, keyboard explanations and canonical save/reopen. The metadata has no file or authorization authority.

The headless `python3 tools/native_addon_server_probe.py --java-home /path/to/jdk21` separately checks dedicated-side loading and the common derived record codec, with no client document initialized. Its marked loopback-only server uses an ephemeral port, flat seed 42 and a bounded 2 GiB JVM; it stops itself after the controls and removes the fixture/log.

Add `--registered` to the server runner for the separate two-boot [registered native owner](../../docs/development/native-settings.md) controls. This opt-in probe registers its own COMMON spec and exercises the public native owner through the shared editor. It preserves the real native TOML serializer and reload listeners, tests failure/readback/restart behavior and reopens saved state in another JVM. Ordinary example launches do not register that fixture spec.

Both registered boots also exercise the public [reference-source APIs](../../docs/development/references.md): actual block/tag capture and worker index compilation, identifier syntax/default namespace, unknown-versus-default-air behavior, an actual isolated registry's empty tag, whole-producer exhaustion, missing optional supplier and explicitly admitted server resource names. These are common-side lookup controls, without a native picker GUI or full-pack admission claim.

The same boots separately exercise typed structural services against the registered COMMON owner: dynamic list rows, copying/moving/removal, stale-target field diagnostics, incomplete scalar input and undo, real native preparation and refusal to Save with read-only access. The fixture retains an unsaved draft and verifies unchanged native TOML bytes; this is not recursive-widget qualification.

The launches use ModDev source containers for this ordinary example and its separate probe. The library itself loads from the exact packaged Maven JAR, checked both before launch and inside the game. This is not full Phase 1, integrated/remote-server or pack qualification, or a release.
