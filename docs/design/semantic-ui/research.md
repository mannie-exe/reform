# Research and design decisions

## Inspected source identities

Research was performed on November 25, 2026. Moving documentation is attributed as a dated snapshot; released source is pinned. Exact fetched byte digests and retrieval outcomes are retained in the task's private research manifest. No upstream implementation or artifact is bundled into re:form.

| Source     | Selected identity and status                                                                                                                  | Inspection and applicability                                                                                                                                                                                                                                                                                               |
| ---------- | --------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| SwiftUI    | Apple's public documentation snapshot; individual symbol availability is retained. SwiftUI is not a separately versioned open-source runtime. | ViewBuilder, State, Binding, Environment, ViewModifier, Layout, NavigationStack, accessibility child behavior, and Apple's identity/lifetime/dependencies explanation. Current docs also describe Xcode 27-specific changes; this design relies on the established conceptual contracts, not that future compiler surface. |
| Solid      | Stable `solid-js@2.0.3`, released November 19, commit `68406c2077eff22c67f71db4a16bf7026ddceee1`.                                             | Package metadata, actual client flow implementation, migration guide, async fundamentals/derived rules, and frozen design records. SwiftUI's distinction between ephemeral view values and identity-bound state is a useful basis for stable lifetime reasoning. Binding projects a source of truth rather than owning it; Environment supplies inherited values. Adopt those concepts, while keeping re:form's actual document edits asynchronous and owner-guarded. Apple documentation does not establish Java threading or permit mutations through a borrowed renderer. [Identity and lifetime](https://developer.apple.com/videos/play/wwdc2021/10022/), [State](https://developer.apple.com/documentation/swiftui/state), [Binding](https://developer.apple.com/documentation/swiftui/binding), [Environment](https://developer.apple.com/documentation/swiftui/environment).

SwiftUI's Layout protocol separates size computation and child placement, and modifiers express compositional transformation. Use measured composition and immutable modifier descriptions without adopting Apple's compiler/property-wrapper machinery. The actual Apple JSON documentation was inspected where the public page required JavaScript. [Layout](https://developer.apple.com/documentation/swiftui/layout), [ViewModifier](https://developer.apple.com/documentation/swiftui/viewmodifier), [ViewBuilder](https://developer.apple.com/documentation/swiftui/viewbuilder), [NavigationStack](https://developer.apple.com/documentation/swiftui/navigationstack), [accessibility grouping](https://developer.apple.com/documentation/swiftui/accessibilitychildbehavior).

Solid's stable announcement dates 2.0 to November 16. The pinned flow source supplies `For` key modes, `Repeat`, `Show`, `Switch`/`Match`, `Loading`, and `Errored`; these supersede misleading 1.x-only comparisons. Frozen RFC files identify themselves as history and direct readers to migration/runtime rules. This design treats those records as rationale and checks names/behavior against the selected package source. [Release announcement](https://www.solidjs.com/blog/solid-2-0-the-long-hold/), [2.0.3 source](https://github.com/solidjs/solid/tree/68406c2077eff22c67f71db4a16bf7026ddceee1), [flow implementation](https://github.com/solidjs/solid/blob/68406c2077eff22c67f71db4a16bf7026ddceee1/packages/solid/src/client/flow.ts).

The pinned Solid ownership record makes nested roots owned by default; its current async rules distinguish committed content, pending changes, loading boundaries and holds. Adopt scoped subscriptions, pure derivations and bounded replacement, but do not import invisible suspension/optimistic rollback as persistence semantics. re:form's confirmed save and unknown application require independent receipts. [Ownership rationale](https://github.com/solidjs/solid/blob/68406c2077eff22c67f71db4a16bf7026ddceee1/documentation/solid-2.0/02-signals-derived-ownership.md), [async rules](https://github.com/solidjs/solid/blob/68406c2077eff22c67f71db4a16bf7026ddceee1/packages/signals/docs/RULES-FUNDAMENTALS.md), [migration](https://github.com/solidjs/solid/blob/68406c2077eff22c67f71db4a16bf7026ddceee1/documentation/solid-2.0/MIGRATION.md).

Base UI's public docs distinguish a predefined-value Combobox from free-form Autocomplete, and compose components from parts. Its controlled helper fixes ownership mode at initial construction. Adopt explicit part relationships and value ownership, but reject merged effect callbacks or silent ownership-mode changes. A native field whose domain admits unknown IDs must not become catalogue-only. [About](https://base-ui.com/react/overview/about), [releases](https://base-ui.com/react/overview/releases), [composition](https://base-ui.com/react/handbook/composition), [Combobox](https://base-ui.com/react/components/combobox), [Autocomplete](https://base-ui.com/react/components/autocomplete), [Field](https://base-ui.com/react/components/field), [Dialog](https://base-ui.com/react/components/dialog).

## Adopt, adapt, reject

| Inspiration | Adopt                                                                                                                            | Adapt                                                                                                                                                                                        | Reject for this architecture                                                                                                                                    |
| ----------- | -------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| SwiftUI     | Fluent immutable declarations, component factories, typed modifiers, environment and stable identity.                            | Component factories mount once per identity; typed `Read` projections update retained controls. No mandatory whole-body reconstruction. Owner-bound edits have result/currentness contracts. | Porting property wrappers/result-builder syntax, assuming structural position preserves reordered draft rows, or treating UI state as the persisted document.   |
| Solid 2     | Explicit owned branches/keyed lists, disposal, dependency-driven derived values, loading/error boundaries.                       | Dependencies are declared typed reads; scheduling runs on the actual native owner thread. Async presentation wraps existing operation scopes with explicit receipts.                         | JavaScript runtime, implicit writes in derivations, optimistic persistence rollback, server-function RPC, or automatic adoption of every 2.0 hold/reveal rule.  |
| Base UI     | Intrinsic behavior separated from decoration, labelled parts, controlled values, focus and overlay rules.                        | One semantic command owns activation; visual replacement must preserve that behavior and actual guarded binding.                                                                             | DOM/ARIA as a native accessibility implementation, CSS props, multiple merged effect handlers, or mode changes that create another value authority.             |
| Playground  | Retained builders, owned child placement, immutable props/patches, generational handles, keyed reconciliation, semantic actions. | Native widgets/render extraction stay Minecraft-owned; scope disposal records failures instead of assuming nonthrowing destruction.                                                          | Its renderer, SDL/window ownership, AccessKit bridge, assets, unconstrained native rebuilds, or numeric stepping policies that conflict with re:form's domains. |

Playground's authoring contract explicitly says construction creates retained objects, while its keyed collection preserves nodes by key through reorder. Its async view owns observation separately from the request. That is stronger evidence than describing it as a literal SwiftUI clone. Source references are `include/ui/Builders.hpp`, `include/ui/collections/Collection.hpp`, `include/ui/Semantics.hpp`, and `docs/ui/{GUIDE,CONTRACTS,CONTROLS,ASYNC,ACCESSIBILITY}.md` at the inspected revision. No source code is copied into product modules.

## Decision log

| ID  | Decision and consequence                                                                                                                                                   | Alternative and reason                                                                                                                            |
| --- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| D01 | Two designs share one kernel and one owner/action model.                                                                                                                   | Independent minimal/full frameworks would require migrating twice and duplicate authority.                                                        |
| D02 | Immutable declaration plus identity-bound mounted scope; fine-grained explicit typed reads.                                                                                | Full-tree VDOM/body reconciliation is unnecessary for current retained native controls; raw mutable widget construction lacks safe composability. |
| D03 | Explicit dependency inputs with pure map/combine; dynamic dependencies are replaced only through owned branches.                                                           | Implicit thread-local tracking is harder to audit across Java native/worker boundaries and is not needed for the demonstrated UI.                 |
| D04 | `Show`/`Switch` dispose view descendants by default; `Disclosure`/tabs may suspend explicitly while retaining bounded session state.                                       | A single hidden/disposed state either loses input or retains unauthorized/native descendants.                                                     |
| D05 | Keyed repeat requires stable domain/draft-row keys; index slots only for noneditable fixed-count decoration.                                                               | Automatically using index/object identity would rebind invalid input to another row.                                                              |
| D06 | Action binding differs from writable local state and cannot be synthesized from a setter.                                                                                  | A universal two-way binding would conceal permission, pending work, failed edits and persistence boundaries.                                      |
| D07 | Async state is explicit and operation-backed; previous content is labelled stale when retained.                                                                            | Solid-style held reveal is useful inspiration but cannot certify disk/runtime outcomes or hide requested context.                                 |
| D08 | Picker accepts only by click/Enter; arrows inspect/audition. ID completion is free-form and manually accepted.                                                             | Selection-follows-focus would stage accidental edits during keyboard browsing.                                                                    |
| D09 | Profiles audition has an explicit Models/Artwork role; initial role Models, clearly labelled and independently switchable. Appearance fixes its role to the edited field.  | Guessing a role from contribution counts would reject valid empty/inherited profiles or preview the wrong candidate.                              |
| D10 | Automatic preparation is opt-in per graphic declaration. State acceptance/audition/draft change enqueue; entry and resource reload require an explicit request by default. | Preparing everything on entry/reload makes browsing unexpectedly expensive and weakens lazy Home.                                                 |
| D11 | Camera is view state: preserve orbit/zoom; geometry refits a framing scale without resetting orbit; Reset returns the provider initial view.                               | Copying provider camera on every READY publication causes the observed reset.                                                                     |
| D12 | Text ancestor links remain navigable; current crumb is noninteractive, highlighted and underlined. History arrows are a neighboring toolbar.                               | Pure dead ancestor text would remove useful existing navigation; boxed buttons violate the requested presentation.                                |
| D13 | Overlay portals retain logical ancestry/authority but use root-clipped placement and modal input eligibility.                                                              | Native Screen nesting or unrestricted out-of-tree widgets duplicates ownership and focus.                                                         |
| D14 | Native narration is the initial accessibility output.                                                                                                                      | An OS bridge/IME/gamepad promise requires separate adapters and native evidence; Playground support is not Minecraft support.                     |
| D15 | Replace Phase 2 as a planning bucket with named packages; retain original text and requirements as history.                                                                | Deleting the old scope or keeping competing active plans loses obligations or creates ambiguity.                                                  |
| D16 | Keep authored layout order in visual, keyboard and semantic projections.                                                                                                   | CSS-like visual reordering can make navigation and narration disagree.                                                                            |
| D17 | Base UI part substitution preserves required role/state/action bindings; composition cannot merge two effect commands.                                                     | Generic callback merging can save/apply twice or bypass readiness.                                                                                |
| D18 | Hard source/domain/admission limits remain separate from view row counts and timing policies.                                                                              | Shrinking legal data to fit a widget would change consumer semantics.                                                                             |

These decisions select design semantics, not product implementation. Remaining native metric values and target-specific API constraints are implementation gates in [acceptance](acceptance.md), not gaps in the state/effect model. If a later measured constraint contradicts a decision, record an explicit contract revision and affected lineage rather than silently changing a fixture.
