# Local profile import

`DocumentActions.imports(source, formats)` attaches one import review to its actual editor, definition, context and READ access. Replacing that review closes its earlier work, preserves the shared editor/history and releases its prepared drafts. `DocumentImports` supplies typed preview and stage operations for GUI, command and internal callers. The generated form supplies a native review screen; [verification](verification.md) records runtime scope. A registered-source Brigadier presenter remains required.

## Admit a source and format

`ImportSource` is a registered capability, not a filename lookup. Its source identity and label are descriptive. The actual owner declares its byte bound, source authorization/lifetime check and capture procedure. Capture runs on the owner executor and returns an immutable-input reader for admitted workers. File IO and parsing must not run on a render/tick thread. A custom source must enforce its byte bound while reading, before constructing a large buffer; the service also checks the returned owned input against both source and format admission.

`ImportInput` defensively owns the captured bytes and records their exact SHA-256, byte count and human label. `ImportSource.snapshot(id, input)` supplies already admitted immutable content. Creating a snapshot does not read a file, fetch a URL or obtain authority over a document. A GUI may explicitly admit a locally chosen file; a server/command integration must supply registered sources and cannot accept an arbitrary client path or URL. No native file chooser or general server filesystem reader is provided by this slice.

`FileImportSource` supplies a read-only regular-file adapter for an explicitly admitted absolute path. Construction/capture creates nothing; its worker reader checks regular non-symlink input, size and a bounded read. Unicode/spaces in a selected filename remain intact. A supplied source guard runs on the owner executor. This adapter has no write capability, chooser, URL fetch or automatic server path resolution. It preserves the exact bytes actually read, rather than promising an atomic snapshot against an unrelated process rewriting a file or its ancestor directories. Changes after preview do not replace the frozen content being reviewed/staged.

`ImportFormat<T>` binds to the exact actual `DocumentDefinition<T>` instance. Matching document names are insufficient. Its parser runs on an admitted worker and returns a raw draft plus an honestly declared optional source schema version. Owner-specific parsers retain responsibility for their source format; this is no implicit legacy migration facility.

`JsonImportFormat` requires explicit `VALUE_JSON` or `SCHEMA_ENVELOPE` selection. Value JSON is unversioned; the service does not invent a source version from the target schema. A versioned document contains exactly `schemaVersion` and `values`, with the positive target version. The shared `JsonEnvelope` selector preserves original numeric spelling and explicit nulls. Wrong versions, unknown envelope fields, duplicate keys, malformed UTF-8, trailing documents and JSON/draft budget failures refuse without altering the editor. Existing `JsonStore` file diagnostics retain their original `storage.envelope` and `storage.schema` codes.

## Preview and stage

Preview captures an identified editor snapshot, captures/reads the source, validates the imported draft under the actual editor's limits and computes typed semantic differences through the same comparison implementation as ordinary document actions. Publication rechecks document READ, source authority/lifetime and the exact session/generation/version/source revision. Later typing refuses the old result; it does not silently retarget it.

The public preview contains source/format/target identity, content digest, optional source version, current/imported diagnostics, authored-change state and typed changes. Its separate input-change flag includes inactive/session input absent from authored or typed comparisons. An unavailable semantic comparison is explicitly distinct from an empty successful comparison. Collections remain whole-field changes without qualified persistent row identity. Comparison row/text exhaustion refuses the complete preview; it does not credit a truncated comparison.

The format explicitly chooses `REFUSE` or `ALLOW_REPAIRABLE` for invalid drafts. Repairable admission preserves invalid fields and diagnostics, requires completed validation and never claims a valid candidate. `draft(actualPreview)` exposes the retained immutable raw draft for explicit read-only presentation without repeating parsers/codecs during rendering. A native presenter must show the diagnostics and unavailable comparison honestly before offering replacement. Incomplete/unavailable validation cannot produce a stageable preview.

Stage accepts only an actual issued, retained preview from this review instance. It rechecks current READ/source authority and the exact reviewed target, consumes that prepared ticket and queues one strict `EditorActor.stage` change. The worker checks the same exact target again. Pending save/conflict handling remains with the [editor](editing.md); a failed stage needs a new preview. A second stage or an expired/foreign review is refused. Undo restores all earlier work through the same editor history. Neither preview nor stage saves a source, publishes runtime state, builds resources or admits a world recipe. Actual saving/application/world admission remains separately authorized and revalidated.

Closing the import review requests cancellation and drains an already-entered reader without treating cancellation as rollback. Late results cannot publish a new prepared ticket. The borrowed source, editor and executors remain owned by their callers. Closing the parent document actions/context also closes the review.

## Native review

The generated `SettingsScreen` offers **Import…** when local edits have settled and no save/conflict acknowledgement is pending. Its default formats are explicitly selected document-value JSON and the versioned JSON envelope, bound to the actual editor's limits and definition. Opening the screen reads no file. `ImportScreen` can also be composed with explicitly supplied owner formats, captions, availability and return/abandon callbacks, and can select an already registered `ImportSource`.

Choose a local file through the native dialog or drop one absolute local file path into the screen. The dialog admits a chosen local file without guessing its format; the explicit selected parser governs it. The chooser uses Minecraft's borrowed IO pool and its existing LWJGL Tiny File Dialogs dependency; it adds no executor, parser, server path command or configuration source. One library dialog may be outstanding. Closing the screen prevents a not-yet-entered chooser request from opening and ignores an eventual result. Once the native dialog has entered, cancellation does not pretend to close it. No file bytes are read until explicit **Preview import**.

Preview shows source/target and editing context, honest source-version metadata, complete available diagnostics and semantic before/after values. Shared field captions retain the same consumer translation keys as ordinary controls. Fresh results reveal the review or imported diagnostics in the measured scroll panel. Narrow viewports retain wrapped footer actions. **Stage draft** returns to the same parent editor and its single Undo/Redo history; invalid input remains visible for repair and cannot become a valid Save merely because staging succeeded. **Back** retains earlier editor work. A retired widget callback cannot replay an import.

Progress and cancellation render cached operation state; native text receives supported Component/string/number/boolean values, not raw enum objects. Source capture/authorization stays on the actual native owner; a held worker read must leave controls responsive. The actual operating-system chooser, file-drop dispatch, renderer and complete authoring flow have separate qualification boundaries. The fixture uses native controls and the public drop callback, not a physical drag device or an automated native dialog.

## Bounds and update checks

Standard admission permits sixteen formats, eight retained prepared drafts, one MiB per admitted source/format, 256 semantic changes and 65,536 comparison characters including field locations. The separate operation scope admits four active/eight retained jobs and two descriptors; operation inputs contain only a registered format identity or a scoped preview UUID. These logical bounds are not a measured heap/cost guarantee and do not change the existing sixteen document-action definitions. Prepared tickets evict oldest-first; retained job metadata does not itself retain the imported raw draft.

Retain the core/public controls for source/format identity, reentrant registration, document/source permission revocation, worker/native capture ownership, invalid-draft policy, exact byte/version/encoding bounds, stale target/source replacement, cancellation/close, ticket eviction, complete comparison and one-step undo. Changes to parser/envelope/typed comparison must also run existing storage and document comparison controls. Native chooser/drop paths, widgets, translations, command dispatch, font/accessibility and real consumer contexts require their own runtime evidence. Preserve bounded root crash evidence before removing failed fixtures; a log tail may omit a render exception's cause. [Verification](verification.md) and [coverage](coverage.md) own those limits.
