# Editing model

The experimental core provides pure edit sessions for scalar, record, list, set, map, optional, defaulted, tagged and custom value types. This model performs no persistence, authorization, runtime publication or game operation. The [JSON owner and editing actor](owners.md) connect it to those services. [Coverage](coverage.md) owns the remaining Phase 1 scope, including native gateways and presentation.

## Drafts and candidates

`DraftTree` is immutable. `DraftNode` retains raw scalar text, record fields, ordered rows, opaque custom/unknown data, missing values and explicit null separately. Invalid or incomplete text never constructs a partially valid owner object. An empty text value can be valid; an absent required field or null for a non-null type cannot. Wrong saved scalar kinds remain visible rather than being coerced. Unknown fields are retained and block a candidate until explicitly resolved.

`DraftTree.fromParsed` preserves original number spellings through unrelated edits. Editing accepts raw numeric text separately from its JSON representation; admissible non-JSON decimal spellings are normalized only when producing candidate JSON. The raw draft remains intact. Custom types currently use an opaque bounded JSON branch; a custom editor and richer nested diagnostic mapping require their explicit extension work.

Rows have random session UUIDs independent of index or serialized value. Moving a row preserves its ID; removing and replacing it does not reuse the old ID. IDs never enter authored JSON. `SourcePath` addresses encoded property/index locations and distinguishes an object property's key from its value; a candidate freezes the mapping from those positions to stable editor paths. An asynchronous diagnostic follows its original row after movement, becomes stale after a value change and reports removal rather than redirecting to a new row at the same index. Source paths are structured metadata, not JSON-pointer or filesystem capabilities.

`DraftNode.Mapping` retains each raw entry before constructing a Java map. Duplicate, invalid and missing keys, malformed rows and unknown entry fields remain available for explicit repair. A row's `FieldPath.Part.KEY` and `VALUE` are distinct from ordinary record fields named `key` or `value`; nested paths continue through the part's declared type. Renaming a key preserves row identity. Duplicate decoded keys receive a primary key-path diagnostic related to the first conflicting row. Map reordering does not make the draft dirty, while raw duplicate counts and incomplete values remain meaningful draft content. Object and explicit entry-list encodings retain their different source addresses.

Sets use `DraftNode.Sequence` with explicit unordered semantics. They retain invalid and duplicate raw members with stable row IDs before constructing a Java set. Duplicate diagnostics relate the current row to the first conflicting member. Reordering remains undoable presentation state without making the document dirty; duplicate counts still matter. The renderer checks ordering against the declared shape, so marking an ordinary list unordered cannot change its persistence semantics. Unique ordered lists retain meaningful order.

Inspection is explicit and pure. Leaf checks describe empty, incomplete, invalid, unavailable or valid input; complete document/cross-field validation is still required before a `Candidate<T>` exists. Candidate values and source maps own their state. A candidate is neither permission nor a persistence receipt. Declared validators/snapshot callbacks must be pure, thread-safe when used on a worker, and bounded; this API cannot sandbox consumer code.

`DraftLimits` bounds depth, nodes and retained characters before a tree replaces session state. Defaults allow depth 128, 16,384 nodes and 131,072 characters. History defaults to 128 entries and a logical retention cost of 1,048,576. Cost counts characters, structural nodes and entry overhead conservatively; it is not measured heap bytes or a wire limit. Owners must also choose appropriate `JsonLimits`. Opaque JSON is structurally admitted during inspection rather than masquerading as one validated leaf.

## Defaulted field state

`DraftNode.Defaulted(overridden, value)` separates source presence from the retained raw override. `FieldPath.Part.VALUE` addresses the payload independently of a record field named `value`. Missing source fields begin with an owned copy of their declared fallback. Explicit null and invalid overrides remain explicit and invalid when their declared type rejects them.

Using the default omits the field and ignores the inactive override during candidate validation. Its raw input, rows and history remain local and count toward draft limits. Re-enabling the override restores that input. Inactive work is not persisted; a fresh session recreates its fallback. Authored dirty state tracks source presence and active values, so changing only an inactive payload does not imply a file change.

Equal-value acknowledgements can adopt a serializer's omitted-default representation while retaining inactive input and later overrides. When a serializer instead materializes an omitted default, the actual saved value becomes active and distinct inactive input is retained separately. These immutable snapshots have stable UUIDs for explicit recovery/discard, count toward draft/history limits and never enter serialized data or authored equality. Collection identities transfer from inactive input only when that input independently decodes to the same value; an unrelated equal document value does not establish row identity. Recovery uses the retained UUID rather than a potentially stale row index.

Omitted fields receive no invented encoded address. Manual conflict review treats a defaulted field's presence and content as one choice. The native recursive form supplies explicit default/override and retained-input recovery controls; richer provenance presentation remains required.

## Optional membership

`DraftNode.OptionalValue(present, value)` separates empty membership from the retained raw child. `FieldPath.Part.VALUE` addresses that child. An empty source starts with a missing child rather than an invented default; enabling it requires authored input or an explicitly supplied consumer seed. Disabling it preserves invalid text, nested rows and undo while excluding them from serialization, validation and authored dirty state. The inactive child still counts toward draft/history limits.

Singleton-list optionals map their active child to encoded index zero; nullable optionals map it to the same encoded source location. Empty membership has no encoded child address. Equal-value acknowledgements retain inactive input and active collection identities; later membership/input edits survive. Manual conflict choices include membership and content together. Old source diagnostics become stale when an ancestor optional or default override is disabled, even when its raw text is retained unchanged.

Malformed encodings remain opaque repairable drafts; they never silently become empty. Nullable nested emptiness that cannot be represented stays invalid in both raw rendering and typed encoding. The native recursive form supplies membership and blank-repair controls.

## Tagged branches

`DraftNode.Alternative` retains a selected ID, branch drafts by stable declared ID and unknown envelope fields. `FieldPath.Part.KEY` addresses the discriminator independently of a field named `kind`; `FieldPath.Variant(id)` addresses a retained payload. Only the selected branch enters authored data and candidate validation. Inactive invalid input, row identities and history remain local, count toward limits and can be explicitly discarded by inactive ID.

`select(id, seed)` creates a missing branch from an explicit seed and restores an existing branch unchanged. It does not infer a valid default, reinterpret unknown payloads or replace unfinished input with a supplied seed. Unknown tags retain opaque payloads; unknown fields remain errors until explicitly repaired. A malformed envelope/tag retains the complete opaque input for repair rather than selecting a fallback.

Equal-value acknowledgement normalizes the actual saved branch while retaining private branches and their later edits. A later selection retains its own payload. Old diagnostics retain their branch target and become stale when that branch is inactive. Whole-alternative conflict choices cannot pair one selector with another branch's payload. The native recursive form supplies branch selection, inactive-branch discard and blank repair; richer recovery/review presentation remains required.

## Public structural edits

An immutable session snapshot exposes its actual editor UUID separately from its owner context. `snapshot.target(path)` creates a `DraftTarget` containing that editor, baseline generation, exact draft version and declared stable path. `EditSession.execute(DraftEdit)` refuses foreign, reloaded or stale targets before changing history. This is identity/consistency checking, not authority. Native providers still check their actual actor and rights.

`DraftEdit` is data, with explicit actions for canonical or [unit-mapped scalar input](numbers.md), insert/duplicate/remove/move rows, optional membership, default override, selected/inactive branches, retained-override recovery/discard, unknown-field removal and blank repair. Collection operations use row UUIDs and optional before-row anchors; an absent anchor appends. They never retarget a visible numeric index after reordering. Copies receive fresh identities throughout nested rows and retained payloads. Raw duplicate set members/map keys remain present with diagnostics until repaired. Collection growth respects the declared bound, while oversized imported collections remain removable.

`ChangeScalarRows(append, remove)` stages explicit scalar/reference additions and stable-row removals as one undoable change. Unchanged rows retain their input, identity and order; new rows receive fresh identities. The complete batch respects collection and draft budgets before publication, with no truncated subset or partial history entry. Removal-only batches can repair oversized imported collections incrementally. Lists retain duplicates/order and sets retain their declared unordered semantics and duplicate diagnostics. The action admits at most 256 membership changes and 131,072 raw characters, with 32,768 per added input; the actual owner/draft may impose tighter limits. It is not a recursive patch or a searchable picker by itself.

`DraftTypes.at` resolves the declared type at an actual active record/row/map-part/variant path. An inactive payload or unknown field cannot become an editable declared leaf. Unknown fields require explicit removal at their owning record/envelope. A malformed subtree requires explicit `Repair`; replacing it with its blank shape is undoable. Blank numeric/boolean/choice leaves remain incomplete instead of inventing a valid value. Blank required text can be valid under its declared codec. Blank construction is depth/node/text bounded and performs no domain compilation or external lookup. Enabling a missing override uses its actual declared fallback; re-enabling retained input restores it unchanged.

Exact-version targets are required for structural/destructive actions. `target.typing()` explicitly permits an ordered raw-input stream to follow edits within the same editor generation. The actor additionally carries that stream across its own save acknowledgement in the same editor UUID; it refuses invented future generations, streams preceding explicit conflict resolution, reloads and lost/inactive targets. The pure `EditSession.execute` generation check remains strict. The actor coalesces matching scalar typing for undo. Frontends must dispose obsolete streams and retain their request/draft identities rather than installing a late input event into a replacement screen. Asynchronous choice application should use the exact-version target, together with its reference-source epoch.

`DraftEdits.type()` admits these requests through the normal strict record/tagged codecs and snapshot limits. It is a local operation input, not a generic JSON patch or remote protocol. `EditorActor.edit` maps a `DraftEditRefusal` to field-attributed policy diagnostics; `DocumentActions.edit(entry, request)` shares that service across frontends without granting Save. Snapshots, validation and comparison/export references retain the actual editor UUID. Native collection services, the public compound example and recursive widgets have separately attributed qualification.

## History and lifecycle

`EditSession<T>` belongs to its creating thread by default. The explicit advanced `fromDraft` overload accepts a trusted owner verifier for a serialized worker adapter; that adapter must enforce serialization rather than disabling checks. `EditorActor` supplies this verifier from its active worker task and removes it afterward, so editing may move between workers without concurrent mutation. Immutable snapshots may be inspected on an admitted worker when definition callbacks support that contract. The pure model owns no global executor, timer, file watcher or screen reference.

`EditSession.stage(exactRootTarget, draft, label)` supplies the reviewed replacement boundary, separate from source parsing or permission admission. It requires the exact root/session/generation/version and refuses pending submissions or conflict review. It applies one bounded history entry, retains wholly unchanged input subtrees/row IDs, and retires old input streams only when the draft actually changes. Complete input equality includes inactive payloads, retained overrides, mapped input and row display order while ignoring generated row UUIDs; active authored-value equality remains separate. An imported inactive payload cannot disappear merely because its saved value is currently omitted. A no-op preserves generation, redo and input ownership. Budget/label/stale failures leave the prior state intact. The older low-level `stage(draft, label)` remains explicitly caller-managed.

`EditorActor.stage` serializes that boundary on its existing lane and updates the typing floor for a real replacement. It does not persist, publish or admit a world. Existing save receipts cannot be invalidated by this operation: a pending save must finish/reconcile first. Format/source admission, preview/semantic comparison and GUI/command import orchestration remain separate required work.

Field typing coalesces only within an explicit `EditGroup`. Compound imports use `stage` as one undoable draft operation. Undo/redo, reset to defaults, revert to the observed baseline and reload are distinct. No-op reset preserves redo and unchanged row identities. Moving identical-valued rows can still be an intentional identity change; authored equality alone does not erase that history.

History is bounded and its oldest retained entries may be removed. A normal edit clears redo. Explicit `discardHistory()` clears only the journals, retaining draft, baseline and pending operation; it can permit reconciliation after an over-budget historical branch without discarding current work. Reload replaces the observed baseline, clears history and invalidates old work; it is not an undoable edit. Close invalidates pending callbacks and clears history/operation references. It does not write, cancel an external operation, roll back a backend or promise that a still-retained session object contains no draft data.

## Submission and acknowledgement

`prepareSubmission` validates the entire current draft and freezes one `Submission<T>`. It binds definition, session/context UUIDs, baseline generation, draft version and the opaque observed saved revision. A submission is prepared before external effects; `markInFlight` and backend acknowledgements are explicit. The owner must still recheck authorization, context and persistence preconditions at its actual effect boundary.

Only one submission is pending at a time, while later editing remains available. A prepared operation can be discarded before dispatch. An unknown outcome blocks another submission until actual reconciliation; this model does not blindly repeat a write or infer unchanged disk from an exception. Confirmed unattempted/refused/failed results release the pending slot only when that classification is established by the backend.

Acknowledgement accepts an actual observed value/tree and saved revision. Equal typed saved values can normalize authored spelling and retain submission row identities. Ordered lists align by index; maps align by their declared decoded key equality and sets by decoded member equality, including when a backend changes order or normalizes spelling. This happens only after complete typed equivalence, never as a heuristic for a changed collection. Nested set/map/list identities compose under those same rules. Known later field edits remain intact; changed collections stay whole. Both history journals and the resulting draft are prepared and checked before baseline advancement. A failed observation/rebase preserves all of them and retains an observation-unavailable pending state. The explicit `observationUnavailable(submission)` transition also retains this state when the backend saved but could not return an authorized observation. Neither claims unknown disk persistence.

If the actual saved value differs and later edits exist, the draft remains intact and an explicit review is required. Without later edits, the observed value becomes current and redo is rebased onto that observation. Reload or close makes old acknowledgements stale; they cannot change the replacement session baseline. Foreign session/context tokens cannot target this session.

## Manual conflict review

`reviewConflict` binds baseline, observed and draft trees to an actual observed revision and current session version. Each changed record field needs an explicit baseline/observed/draft choice. Collections, opaque data and incompatible structures are whole-value choices. Automatic structural merging is not implemented. An acknowledgement-created review uses the submitted tree as its comparison baseline; an ordinary conflict review uses the session's previous observed baseline. Presentation must identify that basis honestly.

Choices are checked as one complete bounded change. Resolution updates the observed baseline/revision, preserves the selected draft and clears obsolete history. Any edit after review invalidates its choices. Resolution neither saves nor guarantees validity: complete validation remains mandatory on the next submission. Missing, invalid or unknown observed data may be reviewed without inventing a valid backend result.

The [independent headless consumer](../../examples/headless/src/main/java/example/ReviewProfile.java) exercises invalid drafts, history, delayed acknowledgement, explicit review, reload and a real asynchronous owner/editor save using only the published local artifact. It is not a native GUI or real-consumer migration fixture. [Verification](verification.md) records exact qualification.
