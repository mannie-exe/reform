# Asynchronous owners

`DocumentSession<T>` connects an actual owner to the shared editor. `DocumentRead`, `OwnerObservation`, opaque `PreparedEdit` and `CommitReceipt` separate saved state, context/session identity, one-shot preparation and persistence/application outcomes. Matching identifiers do not make a foreign proposal an issued token. Supported operations are explicit: an owner without an application-only path must refuse it rather than repeat persistence.

`JsonOwner<T>` supplies owned JSON storage and worker-prepared runtime publication. [Unsaved world recipes](world-recipes.md) use actual context admission with no file persistence. [Registered NeoForge settings](native-settings.md) supply their actual native serializer/callback path through the same editor boundary. These are experimental explicit-infrastructure APIs. Other actor gateways/factories/backends, complete operation/cancellation views and real consumer migrations remain required by [coverage](coverage.md).

## Construct one document owner

Create `OwnerContext` with an explicitly admitted native executor, worker executor, native-thread verifier and resource limits. Construct `JsonOwner` on that native thread with its actual `JsonStore` and a maximum number of outstanding document operations. Executors are borrowed; the platform/factory retains their queue bounds and shutdown ownership. There is no common-pool fallback or hidden per-document thread.

The native gateway creates `OwnerContext.Access` using read/write callbacks bound to the actual actor and opens an owner session with it. A GUI or payload must not supply those callbacks. Registration requires the same context; observations and one-shot prepared proposals additionally belong to the particular document session. An identifier, filename, old successful read or complete candidate does not grant permission.

An access can serve several document sessions. Closing one session invalidates that session without closing another session's access or the document's runtime handle. Closing the access invalidates its sessions. Closing the context invalidates all access and native publication, releases queued work and clears executor/actor references. Native lifecycle code must close the context before its executor stops accepting work.

`OwnerContext.onClose` returns an unregisterable subscription. A shorter-lived editor closes that subscription when it closes, releasing its captured state and active hook capacity while the game/server context remains alive. Context-close callbacks retain registration order and run outside the context gate; one failure does not skip later cleanup.

## Run the shared workflow

`Session.read()` checks actual READ permission, obtains saved data on the worker and rechecks permission before returning the observation. Browsing does not initialize missing files or publish saved values. Observations contain distinct saved state and effective context/revision; an uninitialized handle contains no substituted defaults.

`Session.initialize()` is an explicit WRITE-authorized lifecycle operation. The backend initializes a missing file from validated defaults using its complete-file create-if-absent contract. Existing invalid or unsupported data is retained. A failed observation can retain only an already qualified effective value in the same runtime context.

`Session.prepare(observation, draft)` inspects a bounded immutable draft on the worker and rechecks READ authority, session and effective revision before returning a one-shot proposal. The original draft remains owned by the editing workflow. `Session.commit(proposal)` checks WRITE permission again at serialized commit admission, then performs guarded worker-side persistence and native-thread publication. A consumed or foreign proposal cannot be replayed. Queue refusal requires a fresh preparation; it never erases the editor's draft.

All actor sessions of one document share a bounded logical lane through persistence **and** publication. A physical file lock alone would permit a second session to act between those stages. A competing session prepared against the prior effective revision is refused before its own persistence. External file changes remain subject to the backend's exact observed-byte conflict checks; this does not create a cross-process transaction.

`Session.applySaved(observation)` reads saved bytes again, refuses a changed saved revision and attempts publication from that actual saved candidate. It performs no file write. It supports application-only retry after a successful save and refused application; it never substitutes a new unsaved candidate for the saved observation. A new observation allows an explicit review of externally changed values.

## Keep editing off native threads

`EditorActor<T>` owns one bound `DocumentSession` with the same actual context and definition instance, plus a bounded serialized editing lane on the admitted workers. It supplies immutable views of raw drafts, validation, observation/operation reports, history availability, conflicts, pending acknowledgement and the latest receipt. Widgets and command presenters read those views and queue operations; they must not invoke `Snapshot.inspect()` during rendering. Definition validation, defaults, undo/rebase/acknowledgement and other pure editing work run inside the serialized worker task, even when the borrowed worker pool uses several threads. Foreign native predicates stay on their admitted native executor.

The view also retains immutable per-input validation states from that same worker inspection. [Local availability rules](dependencies.md) consume these cached states without conflating a valid controller with an unrelated complete-object failure. An observer constructed without input evidence receives unknown dependency input, never guessed validity.

`validate()` returns an identified complete report using pure checks and actual owner preparation without persistence. `inspect()` captures the saved baseline, draft and owner-declared provenance/effective observation; it performs no file write. Explicit `load` reads through the actual owner. Missing data is reported without initialization. Dirty reload creates a manual conflict review; a load result that arrives after intervening typing is refused without replacing it. An invalid saved source is reported while retaining an existing draft. `setRaw`, undo/redo, reset/revert and conflict choices remain pure edits. Typing in the same field uses an explicit history group.

`save` freezes one submitted draft and lets later editing continue while authorization and IO are pending. Actual owner receipts drive acknowledgement and preserve later edits. Saved data without an authorized readback keeps observation-unavailable pending state; an unknown write remains blocked until actual reconciliation. Save returns the backend receipt independently of editor acknowledgement, including when the editor closes after replacement. Closing the actor invalidates its own session and queued edits, unregisters its lifecycle subscription and clears the published draft view; it does not close the shared document/runtime context or pretend an active save was undone.

The `save(DraftRevision, checkpoint)` and `admit(DraftRevision, checkpoint)` overloads add an exact expected revision at the serialized capture boundary. They compare the actual document, context, editor session, generation, version and saved baseline before preparing anything. That comparison runs once; a later ordinary edit does not invalidate the already captured submission. The checkpoint still runs at the existing pre-effect safe points, and actual owner permissions/source checks remain independent. [Conditional submission](operations.md#conditional-submission) exposes this through shared typed operations.

This actor connects JSON and explicit registered native owners. The experimental [native form](presentation.md) is qualified with JSON; the registered native backend separately exercises the actor on a real dedicated server. The [client JSON factory](client-json.md) supplies common client registration/lifecycle wiring. Shared [local operations](operations.md) now supply GUI/command validation, inspection, comparison/export and cancellation; other owner factories and complete operation presentation remain required. Core worker qualification does not establish native lifecycle or UI behavior.

## Preserve truthful outcomes

`CommitKind` distinguishes file persistence from unsaved context admission. `CommitReceipt.acknowledgesBaseline` and `baselineOutcomeUnknown` describe source acknowledgement independently of a saved file; the context owner supplies explicit admission facts. Receipts distinguish `NOT_ATTEMPTED`, `UNCHANGED`, `SAVED`, `REFUSED`, `FAILED` and `UNKNOWN` persistence from application status. They contain separate diagnostics, an observed saved revision where available, an optional newly authorized observation and owner-declared application requirements. `STAGED` and `PARTIAL` do not mean that all domain state took effect. Requirements can identify world/game restart, new-world admission, incompatibility or owner-managed effects.

Losing READ permission suppresses newly observed contents. The JSON backend retains a known successful disk replacement as `SAVED` after permission loss or closure. The native backend separately retains whether mutation started and whether native save returned; without its required authorized readback, it reports final persistence as `UNKNOWN`. A completed callback cannot prove final file contents or arbitrary copied domain state. [Native settings](native-settings.md) owns those distinct execution facts.

Actual WRITE authority is checked on the native executor at operation admission and again for runtime publication. Worker-side file guards check the already admitted operation's session/context lifetime before directory creation and immediately before replacement. Guards run under the file lock and must be synchronous/nonblocking: they never dispatch to or await native code. This is not an atomic transaction between native permission changes and filesystem replacement. A write already admitted before closure can finish; its actual receipt is drained. No callback claims that revocation or cancellation rolled it back.

Unstarted native/worker calls are detached before context-close completions run, even if the borrowed executor will never drain. An active write is not prematurely completed with an unattempted result. Failure without a reliable persistence receipt is conservatively `UNKNOWN`; reconcile saved state rather than blindly repeating the write. Closing queued document operations refuses them without executing their effects. Cancelling a copy returned by `CompletionStage.toCompletableFuture()` does not cancel the underlying operation or imply rollback. The [operation scope](operations.md) exposes cooperative cancellation and actual-result drain without claiming rollback.

## Declared application boundaries

`OwnerObservation.applicationEffects()` supplies immutable, already captured `ApplicationEffects`. It performs no IO or native work when the worker inspects that observation. This is a declaration about future application, separate from a past `CommitReceipt` and from an operation's effect labels. It neither validates a candidate nor changes permission, persistence, publication or domain compilation.

Each rule identifies an actual structural scope, one or more timings and an explanation. Timings cover owner value publication, explicit reload, view reopen, next operation/join, world/game restart, new world, newly generated chunks, incompatibility and owner-managed application. The nearest containing rule replaces a broader declaration; timings are not implicitly merged. An uncovered field is unknown. A rule inside a collection does not certify the whole collection, and absent metadata never means immediate application.

Standard metadata admission permits 1,024 rules, path depth 128 and 262,144 logical characters including locations, timings and explanations; each explanation admits at most 4,096 characters. Explicit limits can admit up to 16,384 rules. Duplicate scopes or exhausted bounds refuse the complete declaration rather than returning a partial policy. These are metadata bounds, not measured heap/cost guarantees. Domain owners remain responsible for truthful scopes and actual application guards.

The JSON owner declares publication of its own runtime value, explicitly leaving other caches/gameplay unqualified. Its constructor accepting `ApplicationEffects` supplies immutable domain notices without changing that publication contract. The [client JSON factory](client-json.md) exposes the same construction option. Creation observations declare original unsaved-context/new-world application. Native Controls declare their existing save/refresh boundary; custom mod input dispatch stays mod-owned. Registered NeoForge observations capture each field's actual restart metadata on the owner thread, with no gameplay-cache reads; restart-free fields remain owner-managed. Their explicit metadata bound follows the registered owner's admitted field count and admits at most `maximumBytes * 32 + maximumFields * 4096` characters, retaining room for long admitted source paths and per-field metadata without imposing a short-name requirement.

The review service retains these declarations even for invalid drafts and includes their text in its independent projection budget. Native inspection shows them separately from observed effective values. Actual saving still requires complete validation, authority and source/context checks; a declaration is not an application success receipt or a safe-worldgen-rebuild claim.

## Boundaries and updates

Owned JSON IO, raw preparation and pure publication validation/copy/equality use the worker. The native executor captures authority/context/immutable inputs and performs final current checks plus the prepared-state swap. A newer runtime observation invalidates older worker preparation even when its effective revision is unchanged. A completed application remains an application fact if context loss later prevents returning an authorized readback. Actual callback costs and GUI/pack responsiveness still require measured qualification. Domain compilation, application requirements, native TOML serialization and new-world admission are not generic JSON publication.

[Storage](storage.md) owns byte/path/atomicity guarantees. [Publication](publication.md) owns effective revision and immutable handle rules. Recheck those contracts, native actor resolution, close ordering and shared-lane/failure controls when changing an executor, owner backend or permission provider. The headless checks do not qualify server/connection gateways, native GUI responsiveness, pack behavior or complete Phase 1 readiness.
