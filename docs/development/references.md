# Reference sources

`ValueTypes.reference(element, source)` adds selector metadata to an existing text/choice `ValueType`. It preserves that type's codec, snapshot policy, authored spelling and structural draft path. It performs no lookup while decoding or drawing a field. Structurally valid unresolved keys remain editable; the owner decides which reference checks are required for validation, publication or admission. Existing native registry codecs still need their actual registry context.

The current implementation supplies reference data, shared local operations, exact draft-bound scalar selection and native scalar/collection pickers. Collection runtime and broader native/context qualification remain tracked in [coverage](coverage.md).

Native scalar and collection browsers show owner-supplied preview facts alongside choices and inspection results. A resolved tag with zero members remains distinct from a tag with members; the library displays the admitted facts rather than interpreting them as domain acceptance. Formatting bounds keys, values, and the complete preview without splitting Unicode code points. Replacing or retiring the source clears current preview evidence. Inspecting a collection entry reveals its result at that entry, preserves keyboard focus, and changes neither the draft nor saved data.

## Complete admitted data

`ReferenceResolver<K,V>` returns `ReferenceResolution<V>` and bounded `ReferencePage<K>` suggestions. Resolution distinguishes resolved, unknown reference, malformed syntax, missing dependency and unavailable context. A resolved empty collection is a real value. A ready empty index is different from an unavailable source. Namespaces identify resources, not installed mods; an unknown namespace alone cannot establish a missing dependency.

`ReferenceStamp` binds the actual owner context, logical source, unique snapshot nonce and descriptive revision. Rebuilding the same revision label produces a different nonce. Each page and result retains its stamp. A continuation also binds the exact filter and next candidate offset; an empty filtered page can legitimately have more candidates. `examined` reports candidates examined, without inventing a total match count.

`ReferenceIndex` owns immutable copies of an explicitly admitted complete collection. It requires unique keys and encodings whose equality/hash survive copying and codec roundtrips. Rows sort by their encoded keys, with locale-independent case and diacritic folding for text search. Authored keys, displayed labels and exact cursor filters retain their original spelling; folding does not alter resolution or identifiers. Producer exhaustion refuses the whole index; a truncated source cannot report an unknown key as a complete lookup. Lookup and pages return independent owned values/keys and immutable presentation metadata.

The unpublished dev.119 source adds `ReferenceQuery.Match.KEY_PREFIX` beside the existing `TEXT` default. Old query/cursor constructors keep text semantics. Cursors bind the matching mode as well as the exact filter and snapshot; a text cursor cannot address a prefix range. `ReferenceResolver.supports(match)` defaults to text only, so an older resolver is not silently asked to interpret a new query. Unsupported matching returns a typed `UNSUPPORTED` page. A resolver opting into key-prefix matching must return only actual string keys beginning with that exact prefix; the owner service validates its results and continuations.

`ReferenceIndex` supports key-prefix matching for string keys. A bounded second row-reference index supplies binary range navigation, followed by at most the admitted page/scan candidates. Prefix offsets count candidates within that exact range. A late ID does not require scanning every earlier text row. IDs use exact Java string identity, including case and Unicode distinctions; text search keeps its existing folding. Numeric and other non-string keys retain text search and explicitly do not supply ID-prefix matches. This service work is model-qualified; it is not yet a qualified native completion popup.

`ReferenceLimits.STANDARD` admits 16,384 entries, 1,048,576 aggregate text characters, pages of 64 choices, 128-character filters and at most 4,096 examined candidates per search. Snapshot depth/visit limits are separate. These are local index/presentation policies, not network, file or universal domain-value limits. Callers select source-specific bounds and explicit snapshot policies. Pure custom providers must bound their own work; an interface cannot sandbox consumer code.

## Actual-owner operations

Construct `ReferenceActions<K,V>` with the real `OwnerContext`, its actual `Access`, logical source, key type, result snapshot policy and limits. Its `resolve` and `search` services use the existing [operation scope](operations.md), require READ and perform lookup on admitted workers. They check fresh authority, cancellation, source identity and context again before delivering an owned result. Choice requests can include the expected snapshot nonce. Providers cannot return foreign stamps, duplicate keys, oversized presentations or continuations inconsistent with examined candidates.

`bind` invalidates the previous source before building a complete replacement. `bindAsync` allows native capture at entry, worker compilation and fresh native publication. Until publication, the source is unavailable. Failed, reentrant or late producers cannot resurrect an old source or overwrite a newer binding. `invalidate` publishes an explicit missing-dependency or unavailable state. Context closure clears the provider and refuses new work; running operations drain through their retained handles.

`bindCaptured` supplies a convenience boundary for native capture and worker compilation: its capture receives the actual owner and assigned stamp, compilation uses that context's bounded worker lane, and publication retains the same fresh-source checks. It adds no executor or resource enumeration. `observedStamp` and `isOpen` provide cached lifetime observations for presentation; they neither authorize reading nor perform a lookup. `requireStamp` separately performs fresh READ admission on the actual owner thread.

## Shared browsing and collection edits

`ReferenceBrowser<V>` borrows one admitted `ReferenceActions<String,V>` source without attaching it to an authoring target. It exposes the same bounded search/lookup handles and immutable results used by scalar selectors. Source identity, fresh READ checks, latest actual request identity and creating-thread rules remain explicit. Starting a replacement clears prior evidence even if admission fails. Reentrant permission/cancellation callbacks cannot let an older request replace or publish over a newer request; closing one browser never closes its borrowed source or another browser's work.

For an explicitly staged choice from a read-only catalogue page, `ReferenceSelection.chooseFromBrowser(entry, document, path, browser)` binds the current inspected ID to one actual field. It checks the field's declared reference source, captures its exact current draft target, rechecks source READ and selection, and submits through the same document edit service. The browser remains independent of document edits, so one catalogue can stage two separate fields without coupling their values. A reentrant field change makes the captured target stale; a changed highlighted choice is refused instead of silently following it. Empty resolved values remain selectable. This stages only; it never saves or applies.

`CollectionSelection<T>` binds the actual `DocumentActions` actor to a scalar list/set path, including direct reference elements. Its cached view retains stable row IDs, raw/malformed input, per-input parse state, declared choices and any reference-source ID. Input validity does not establish resolution. It neither queries a catalog nor treats its current entries as the only permitted values.

`change` takes the widget's captured exact `DraftTarget` and one bounded `ChangeScalarRows` action through the real document edit service. Only the controller's actual issued completion may advance its target; forged completions and competing later edits cannot silently adopt a newer draft. A pending issued edit requires completion before another selection or explicit refresh. Reentrant READ admission cannot issue a second membership edit before the first handle exists. A stale selection requires deliberate refresh. Closing releases only local observations and never retains a newly admitted pending token after closure; the document owns an already-issued edit, with no implicit cancellation, rollback or Save. [Verification](verification.md) distinguishes core, public-artifact and native evidence.

## Native collection picker

Generated `SettingsScreen` forms expose **Choose values…** for boolean/enum collections and direct scalar-reference collections. Inline row editing/reordering stays available. The picker pages existing rows and available choices separately, eight at a time. Lists retain duplicate entries and order; set duplicate drafts remain separately removable. An existing row's parse state never certifies reference resolution. Manual input remains available when a source is missing, unavailable or obsolete, subject to the document's actual authority and complete validation.

Individual additions and stable-row removals use the shared edit action. **Add missing shown** stages only the missing choices on the visible page, as one bounded undoable action. It neither selects hidden matches nor replaces the whole list. Capacity and validation refusal leave the prior draft intact. Back retains staged work; explicit Save remains on the parent. The parent's Undo/Redo controls use the same actor history as its existing platform keyboard shortcuts. No secondary modal history or automatic persistence is introduced.

Known choices use declared metadata and owner-localized labels under the field's existing label key plus `/choices/<raw-key>`. Their complete cached display catalog uses the standard reference entry/text bounds, and explicit filtering scans at most the standard candidate bound per page. Label/search caching is rebuilt when the native language bundle changes. Actual registry/tag/resource suggestions use a borrowed `ReferenceBrowser`, its admitted workers and source-specific limits. No file/resource enumeration or domain preview occurs while painting or typing a filter.

Every edit captures the actual draft target. Retired page/widget callbacks cannot borrow a refreshed target or source. Replacing a source visibly disables its old catalog choices; **Refresh views** explicitly adopts current draft/source observations without changing values. Known/manual entries survive refresh. Source preparation, reload timing, domain validation and publication stay with the consumer. Native rendering, language/font reload and physical-input qualification are reported separately.

## Draft-bound selection

`ReferenceSelection` binds one `DocumentActions` draft target to its declared `ReferenceActions<String,V>` source. It captures the exact editor/session/generation/version/path, original raw key and actual source/context nonce. A changed draft, removed/replaced/moved row, branch switch, save acknowledgement, reload, source replacement or closed context makes that selection obsolete. Equal descriptive source revisions do not preserve freshness.

Search and inspection return the existing operation handles. The frontend marshals completion onto the controller's creating owner thread and calls `accept` with the actual request object. Only the latest completed search or lookup handle may publish its result; callers cannot substitute a different response. Starting another request invalidates the prior response even when fresh admission refuses that new request. Changed queries replace their old results, and closing the controller cancels only its own outstanding reads. The borrowed source and document remain open. Cached `page`/`resolution` observations perform no IO or permission callback.

`choose` requires a resolved lookup, rechecks source READ/nonce and submits its exact raw key through the document's typed edit service. An empty resolved tag is usable; unknown, malformed, missing-dependency and unavailable results are not selectable. Inspecting an authored key never normalizes or replaces it. Selection stages a draft only: it does not save, publish resources, change runtime values or certify domain validity. Source admission occurs at submission, not as a registry lock held through later saving; owners retain complete current-context validation at their actual application boundary. This local controller requires the actual native owner thread for its source and document. It is not a remote bridge.

The experimental native `SettingsScreen` accepts explicit borrowed source bindings. Missing bindings leave manual text intact with an unavailable Browse state. Its auxiliary picker uses bounded explicit search, source-bound pagination, identifier inspection, preview summaries, Refresh and a separate Use selection action. A changed filter cannot reuse its old continuation. Refresh captures a new field/source target rather than reviving obsolete results. Returning preserves the parent editor; unexpected picker removal closes that editor while leaving source ownership intact. Large previews are visibly abbreviated without changing their data. Native runtime qualification is recorded separately in [verification](verification.md).

The [client JSON factory](client-files.md) can create reference actions under its ready actual owner and pass explicit bindings to a screen. The independent `ReferenceExample` prepares block/tag and explicitly enumerated client resource snapshots through public APIs; it owns when those sources are refreshed. Installing the library does not enumerate resources, register a menu or start source reload work.

## Titled reference controls

`ClientFormOptions.withReferenceTitles(source, titles)` opts that source's fields into a title-first presentation. Construct `ReferenceTitles` from an owner-prepared map of exact authored IDs to native Components. The primary button shows the friendly title and opens the same shared reference browser; its tooltip retains the ID and source. **Edit ID** reveals the normal raw controls in the same form. A valid missing ID remains editable and saveable when the actual document owner permits it. Malformed drafts remain repairable. Missing source bindings disable browsing while leaving manual editing available. Existing forms retain their raw-ID presentation unless explicitly opted in. Titled rows retain the field’s declared purpose and supplemental owner facts beside the shared chooser/manual-ID guidance. Invalid collapsed selections keep their actionable diagnostic and exact draft through grouped rebuilds.

The title map is presentation metadata, not a resolver or evidence that an ID exists. An ID without a title displays its authored ID; absent metadata never becomes a default selection. No key normalization is inferred from a display map. Source inspection, nonce freshness and resolved-choice admission still use `ReferenceSelection` and the actual source. Manual editing neither manufactures a resolved choice nor bypasses the document's validation and saving policies.

`ReferenceTitles.replace(map)` publishes a complete copied cache at the owner's chosen resource boundary. The map admits 16,384 entries, 1,048,576 aggregate key/title characters, 32,768 characters per key, and 1,024 visible characters per nonblank title. Invalid or oversized replacements refuse before publication. Form ticks read cached snapshots, raw values, and editing diagnostics; drawing performs no catalogue enumeration, source lookup, or file IO. Changed titles update existing buttons without changing drafts, saving, or publishing resources. The owner retains the cache and its lifetime; closing the form releases the borrowed presentation. Explicit custom `FieldEditors` retain their presentation priority.

## Native snapshots

`design.inherent.reform.minecraft.reference.NativeReferences.captureRegistry` reads the caller's actual current/frozen registry on its owner thread. It captures registered IDs and optional named-tag membership, then returns a `Capture` containing only strings, collections, limits and the assigned stamp. `Capture.build()` can compile the bounded index on a worker. It retains no registry, holder, level, resource manager or renderer. Narrow game-version adapters handle native identifier and named-tag API differences; neither loader owns this service.

```java
var limits = NativeReferences.Limits.STANDARD;
var choices = new ReferenceActions<>(
    context, access, source, ValueTypes.text(limits.maximumKeyLength()),
    NativeReferences.valueType(limits).snapshotPolicy(), limits.index());
choices.bindAsync(reloadRevision, stamp -> {
  var captured = NativeReferences.captureRegistry(
      context, stamp, actualRegistry, true, limits);
  return context.onWorker(captured::build);
});
```

The caller owns actual reload/context lifecycle and closes the actions with its editor/source. Capture occurs explicitly when supplying/replacing data, rather than during typing or selector painting. The native default permits 512-character keys, 4,096 members per tag and 65,536 memberships across the complete source. Oversized sources refuse before publication. Review these defaults against the actual pack/source; raising a bound requires measured admission.

`NativeReferences.type` validates native identifier syntax while preserving the authored spelling. Lookup accepts the default namespace and separately normalizes IDs. Unknown IDs never fall through a defaulted registry's `get` method. Literal/resource results contain one canonical ID; tag results contain the admitted member IDs, including an empty list for an actual empty named tag. Preview data identifies the kind, registry and member count. Results are identifiers, not live native objects or domain acceptance receipts.

`captureOptionalRegistry` avoids invoking the supplied registry provider when its dependency is absent. The caller must also gate construction/linkage of any optional bridge; this helper cannot make an already-linked foreign class safe. `captureResources` receives explicitly admitted resource names as `Collection<String>`; convert native resource keys with `toString()` after the caller's bounded enumeration. It checks the declared text bounds, validates native identifier syntax and normalizes the default namespace before indexing. It does not enumerate files/resources, read their content, generate chunks or invoke a template compiler. Resource enumeration and deeper inspection remain explicit owner operations with their own costs. The 0.1 native-identifier collection signature is a source migration, independent of the preserved string storage format.

Updates to native registry/tag APIs, resource enumeration, executors or reload lifecycle require requalification of default namespace normalization, malformed/unknown/missing/empty distinctions, whole-source exhaustion, copy ownership and off-thread compilation. Retain the actual native context instead of substituting a global registry. [Verification](verification.md) records measured fixtures and remaining limits.

## Semantic picker controller

The revised candidate adds the neutral `ReferencePicker<T,V>` controller in `presentation.ui`. It borrows an existing `DocumentActions<T>`, declared `PickerRole<T>` paths, and a lazy supplier of the actual `ReferenceActions<String,V>`. Roles must match the declared reference source. Construction reads cached editor metadata and admits UI state; it never calls the source factory, creates an actor, loads a file, or searches. `admit()` explicitly obtains the borrowed source and starts the initial bounded search. Closing the controller closes its UI scope and its own browser interests, leaving the source and document lifetimes with their owners.

The host calls `update()` outside rendering/measurement, followed by its normal scoped-observation refresh. Supply a monotonic nanosecond clock. `query()` preserves text/caret/selection and coalesces text changes for the declared 200ms policy; caret-only changes do not search. Enter uses `flushSearch()`, which starts the latest demand without duplicating an already completed current query that the host has not projected yet. Actual reference services still perform searches and lookups on their existing worker lane. One entered request and one latest replaceable demand are retained per search/inspection channel; replacement does not enter before its obsolete predecessor actually drains.

`PickerState` separates the source binding's currentness, query, bounded retained page window, active option, pinned inspection, each role's actual actor raw value, optional native input observation, pending acceptance, and actual service/edit work. A binding can be current while its page reports a missing dependency or unavailable context. Empty pages, incomplete enumeration, unknown IDs, malformed IDs, and resolved-empty values retain their actual distinct facts. No total match count is invented. Inspection state contains presentation facts, not a second copied domain value. Retiring requests expose only their lifecycle facts; details from an old or withdrawn source are not disclosed. Suggestion state also retains the actual entered operation identity, state, and cancellation-request flag through source READ withdrawal and replacement drain. Its report is withheld at that boundary. Withdrawing source content does not itself acknowledge cancellation: requesting cancellation uses the operation's current authority and can be refused after READ loss. The old request must still drain, and its output cannot regain publication authority.

`active()` moves the active option without pinning or editing. `activate()` with no role pins inspection only; a declared role requests an explicit guarded field choice. `acceptInspected(role)` supplies field-specific readiness for separate Use-for-role actions. Read-only browsing does not grant WRITE. Delayed acceptance retains the complete actual draft revision, source/key, and native input observation from activation. Before staging it rechecks the current lookup, source READ, actual field WRITE, input freshness, and original revision through `ReferenceSelection.chooseFromBrowser`. A newer draft, unaccepted native text, changed input epoch, or superseding inspection refuses without replacing that input. Actual edits remain normal owner operations, with no save or application implied.

Native adapters must supply the existing `FieldFrontend` restrictions for attached native inputs; an empty frontend map is for selective use without those buffers. These restrictions can only narrow admission. Actual owner/source checks remain authoritative. The returned `UiActionResult.Pending` names an actual service operation, including a predecessor being drained; it is not a synthetic promise that the entire search-and-edit journey has completed. Observe `PickerState` for the current phase and actual edit receipt. Cancellation is requested asynchronously through the existing owner queue, and hiding/closing cannot claim acknowledgment or rollback from a timer.

`Policy` separates page size from retained pages and cursor history. The default retains four pages and at most 1024 source-issued cursors. `PickerState.window()` supplies the currently admitted choices, first retained page, retained-page/cursor counts, and whether an actual continuation exists on either side. Those counts are not a match total. `nextPage()` and `previousPage()` retrieve only cursors returned for that exact source/query. Evicting a page releases its UI metadata; its bounded cursor can recover it later. The first query continues empty intermediate scan pages through the existing bounded operation lane until it finds choices, exhausts the source, or reports a refusal. Overlapping pages, invalid continuations, and cursor-budget exhaustion report a refusal instead of truncating the source or fabricating an offset.

A completed continuation that has not yet been projected is reused, just like an Enter-flushed search. Old admitted rows remain usable while another page loads, provided their source, query, key, and actual target/input guards remain current. Query/source replacement clears window admission. A pinned title remains attributable even after its original page leaves the window.

`mount()` supplies one lazy `Interest`. Acquisition opens no source. Its first owner-thread update admits the source; subsequent updates drive the existing controller. Only one visible interest can own that driver at a time. Closing it suspends only this controller's browser work and keeps its source/document borrowed. Final controller scope retirement also revokes the interest. Pure projection cannot acquire, update, or close one.

A mounted return retains a bounded, source-stamped position inside the same controller: query/caret/selection, admitted page range and source-issued cursors, active navigation, pinned inspection/title, and list anchor remain distinct. This local metadata uses the existing aggregate UI allowance; it contains no copied resolved value and is not a portable bookmark or edit authority. The returning interest rechecks READ and the actual source stamp, then re-reads the bounded window and pinned value through the existing services. Its new query generation refuses old options. The list position is applied only after the whole return window is ready. A changed source discards the old cursor/active admission, preserves the actual staged raw values and query, and reports that a current choice needs inspection. Explicit refresh or a changed query starts a new position. Hiding still suspends work and exposes no current source rows; no work is entered merely by reading the hidden state.

The native `ReferencePickerView` assembly now consumes this controller through shared list/query parts. Existing reference screens and the production consumer have not yet been replaced. The canonical control surface and source-stamped manual-ID completion are implemented in the selected field host. Native qualification of these return boundaries and complete preview composition remain selected work. [Verification](verification.md) separates existing qualified controls/services from the pending assembled native journey.
